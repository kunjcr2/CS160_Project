## Survey Instructions

As a team, you will come up with questions that you will put into a survey.

As mentioned in class, first think about 5 to 7 key features which you will introduce into your project  (actually think of more features), and then create a form which will be asking a couple of questions about each key features.

You will create a Google form to ask these questions because it can generate an excel sheet which you can refer to, to generate graphs.

e.g. example of a feature:  you have a feature called security settings for a user profile.

An example survey question could be related to using Duo Authentication, 3 security questions in case you get locked out of your account, phone text message with security. Then you might phrase the question in such way like: "Rank the following security options .... from best to least best... or rank each security option from 0 to 10 where is 10 is the best etc.

You can introduce yes or no questions, range/scale questions, have short opinion responses...

Come up with questions with the idea that you want to know if it will be worth the time and effort to implement a feature.

The feedback is what you want to learn about because it will give your team a sense of whether or not to pursue a feature.

It's better to know that what you are doing is worth the effort rather than coming up with an idea without any input about it, and then making you wonder if anyone will use your product after you release it.

*** You will be given the teams # that you will send the survey form to..

## What You Need to Come Up With After You Get the Survey Responses

Create a report that shows the following:

- In a nutshell, you will list all survey questions and their associated responses e.g. display as a pie chart or some graph to compare responses
- Format of the report:  (you'll do this for each question - see steps 1 to 3)
  1. (0) To start off, ask for the Team member's name and what team they are from, and then 
  2. (1) Write the survey questions
  3. (2) Show the statistics of the responses of each question (e.g. graphs ,etc.)
  4. (3) repeat (1) and (2) for the remaining questions
  5. (4) Once (3) is done, summarize which features will you implememt
- List the features that you originally came up with
- It would be a good idea to come up with extra features such as 10 to 12 features, with the idea that some of those might be cut out after you review the responses
- List the features that you will now commit to because of what you read about in regards to the feedback
- You should have at least 5 to 7 key features about your product as result of the decision making 
- It's okay to have more than 7 if your team thinks the extra features can be implemented.
- (5) In the report, make sure you have:
  - a title page ( include course info/semester info/school )
  - the question and statistic set of pages
  - Summary/Conclusion
